## Changed

- **`/feature-test` no longer silently falls back when spec resolution misses** — Step 1a used to set SPEC_BUNDLE empty and proceed if spec-resolve.sh returned nothing, even when the project had `.spec/` with APPROVED specs. Tests generated in that path lost `covers: R<N>` annotations downstream implementers rely on. Now when `.spec/` exists with APPROVED specs and the resolver returns empty, `/feature-test` stops, explains why, and offers three paths: re-invoke with `--specs <ids>`, list spec IDs in `.feature/<slug>/brief.md`, or rewrite the brief. Projects without `.spec/` or with no APPROVED specs proceed silently as before.

- **`/feature-test` gains `--specs <id1,id2>` flag** for explicit spec ID pass-through when fuzzy match misses. Plumbed through to `spec-resolve.sh` via new `EXPLICIT_SPEC_IDS` env var that bypasses domain inference and loads the named specs directly. Feature briefs can also list explicit spec IDs via a `specs:` field in `.feature/<slug>/brief.md` for cases where the author knows the set upfront.

- **`/feature-refactor` now runs inline `/spec-verify` before the adversarial audit pass** — new Step 4a resolves the APPROVED specs this feature touches (via `spec-bundle.md`, `@spec` annotations in changed files, or `work-plan.md` frontmatter), invokes `/spec-verify` per spec as a sub-agent, and handles the verify-and-repair loop inline. Drift now surfaces directly as spec violations rather than masquerading as adversarial findings in the broader Step 4b audit. Skipped cleanly when the project has no `.spec/` directory, when no specs were loaded for the feature, or when running via `/feature-quick`. Pipeline-progress chain updated to reflect the new step.

## Fixed

- **`/audit` now refuses to run against non-APPROVED specs** — when the entry point is `spec:<id>`, `/audit` gates on spec state before dispatching any subagent. A DRAFT or INVALIDATED spec has no authoritative contract, so Lens A SPEC-REQ findings have nothing to prove against — running /audit anyway produces misleading findings a user will mistake for conformance bugs. The gate exits with a clear message and a next-step recommendation (`/spec-verify <id>` for DRAFT, or "point /audit at the replacement spec" for INVALIDATED). Implemented as `scripts/audit-state-gate.sh` and wired into `skills/audit/SKILL.md` between entry-point determination and budget. Feature/file/prior-report entry points are unaffected. Five regression tests in `tests/scenario-audit-state-gate.sh`.

- **`work-validate.sh` now resolves artifact_deps references** — previously it only checked that `required_state`/`required_status` fields were present on spec/adr/wd dependencies; dead references (spec ID not in registry, WD that doesn't exist) and state mismatches (WD declares `required_state: APPROVED` against a DRAFT spec) passed validation and surfaced later as runtime failures during `/work-plan` or `/work-start`. Now resolves each reference: specs via `.spec/registry/manifest.json`, ADRs via `.decisions/<slug>/adr.md`, WDs via scan of `.work/**/WD-*.md`, KB entries via `.kb/<path>.md`. Missing infrastructure (no manifest, no `.decisions/` yet, etc.) emits a WARN and proceeds; found-but-wrong references error out with clear messages. Five regression tests in `tests/scenario-work-validate.sh` (Tests 13-17).

- **`upgrade.sh` no longer prints false "skip … refusing to remove" for kept kit files** ([#45](https://github.com/telefrek/vallorcine/issues/45)) — the stale-file loop now checks the new manifest first and only consults the safety whitelist for actual remove candidates, so files present in both the old and new manifests skip silently. Also adds `.claude/prompts/*` to the whitelist so prompts can be legitimately removed in future versions. Previously a clean v0.13.8 → v0.14.0 upgrade emitted 29 misleading skip messages for `.claude/prompts/audit/*` files that were never going to be touched. Regression test in `tests/test-install.sh` Test 9e.

## Added

- **Curate drift-detection analyses** — `/curate` now surfaces two new spec-drift signals. Analysis 18 enumerates APPROVED specs from `.spec/registry/manifest.json`, invokes `spec-trace.sh` for each, and flags requirements whose `@spec` annotations are missing on the implementation or test side (plus APPROVED specs that have zero annotations anywhere). Analysis 19 enumerates specs with non-empty `open_obligations` frontmatter, computes age from the last commit touching the spec file, and flags obligations older than a configurable threshold. Both dual-schema aware (v1 `features` object + v2 `specs` array). New `curate-scan.sh` flags: `--obligation-age-days <n>` (default 30) and `--max-specs-traced <n>` (default 50, bounds `spec-trace` fan-out on large codebases). Routes: annotation gaps to `/spec-verify`; aging obligations to `/spec-author` or `/spec-resolve`.
